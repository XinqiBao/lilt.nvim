# PoetryDB

PoetryDB provides free anonymous access to a curated poetry collection through
its [documented JSON API](https://github.com/thundercomb/poetrydb#api-reference).
Choose **Discover online → PoetryDB** to browse authors or search titles and
authors. An author's group lists that author's poems. Search matches either
title or author; it does not search poem text. The service supplies no pagination
or reliable total for these queries. If a search is too broad, narrow it rather
than expecting another page. Catalog availability depends on the service.

Each selected poem becomes one plain-text reading unit. Acquisition requires
`curl`, without EPUB conversion or Pandoc. The reference retains every API line,
including indentation, trailing spaces, blank stanza rows, Unicode and source
punctuation. There is no reflow or quotation-mark normalization. PoetryDB's
`linecount` excludes empty rows; Lilt measures saved progress using the actual
physical reference rows.

## Identity and exact selection

PoetryDB has no immutable poem IDs. Lilt identifies a poem by the full SHA-256
of its exact author/title pair, encoded with each string's UTF-8 byte length.
Spelling and case matter. This identifies the recorded pair, not an independently
verified edition. If the service changes a title or author, it can appear as a
different source. A content change alone does not change that identity.

Before preparing a selected poem, Lilt checks that the response contains the
exact author and title. Different records sharing that pair fail as ambiguous;
Lilt never silently chooses the first variant. Identical repeated records can
collapse. An installed copy opens its saved local reference; acquisition never
refreshes text beneath an existing manuscript.

The API uses semicolons and slashes as query delimiters. Search input containing
those characters, or ending in an API modifier (`:abs` or `:word`), must be
shortened. Selected titles containing semicolons or slashes use the exact author
and a safe title fragment to locate candidates, followed by exact pair validation.
An unsupported author/title query, missing poem, ambiguous response or over-broad
lookup produces an error instead of substituting another poem.

## Saved source and attribution

The installed work remains readable offline and includes:

- `001.txt`: the poem's exact API rows, separated by LF newlines.
- `SOURCE.poetrydb.json`: the unmodified complete selected-request response;
  `lilt.json` points to it through `source.file`.
- `SOURCE.json`: the exact selected record and request URL. Optional source
  provenance is retained when PoetryDB records it.
- `README.txt`: attribution, rights links and preparation details.

PoetryDB's published [data license](https://github.com/thundercomb/poetrydb/blob/main/DATA_LICENSE.md)
distinguishes its curated edition/database, licensed under
[CC BY 4.0](https://creativecommons.org/licenses/by/4.0/), from the primary poem
texts, which PoetryDB describes as public domain. Lilt preserves that distinction
as a source claim and retains the published credit:

> Poetry data from PoetryDB (https://poetrydb.org), curated by The Combed
> Thunderclap, licensed under CC BY 4.0.

The service's GPL software license covers its server software; it is separate
from the data license. Preserve the saved source and attribution when sharing.

Lilt records the supplied title and author without guessing an edition,
publication date, publisher, subject or language code. Author biographies are
generated by the service and are excluded from Lilt's metadata. Missing source
provenance stays missing; a poem title alone does not establish its source edition
or an independent rights determination.
